## Achados por prioridade

### 1. Alta: segredos gerados não chegam à API na instalação limpa

`install.sh:31-33` cria .env vazio e afirma que os segredos ficam em .env.docker. Porém docker-compose.yml usa env_file: .env para o backend e só interpola explicitamente DATABASE_URL, WEBHOOK_KEYS, PII_KEYS, PII_INDEX_KEY e DATABASE_CONTEXT_KEY. O override novo não acrescenta JWT_SECRET, EMBEDDING_KEY ou ADMIN_SENHA.

`--env-file .env.docker` fornece variáveis para interpolação do Compose, mas não injeta automaticamente todo o arquivo no container. Mesmo presentes nele, esses três segredos ficam ausentes do ambiente da API, conforme configuração resolvida reproduzida.

O backend em desenvolvimento gera JWT_SECRET e EMBEDDING_KEY efêmeros (backend/app/core/security.py:52-81). Reiniciar o processo invalida sessões e impede decifrar templates faciais persistidos. A reprodução com um vetor sintético cifrado no primeiro processo e lido no segundo retornou None. A alteração não apaga os registros; perde-se a chave necessária para ler os templates gravados com a chave efêmera anterior.

Correção indicada: repassar explicitamente essas três variáveis ao backend, exigindo valores presentes, mantendo fora dele senhas bootstrap/migrador. Adicionar regressão de instalação limpa e reinício. Não usar indiscriminadamente .env.docker como env_file do backend: isso entregaria à API as senhas administrativas do banco.

### 2. Média: senha administrativa gerada é ignorada

É outra consequência da mesma omissão. backend/app/main.py:44-58 usa a senha padrão de desenvolvimento quando ADMIN_SENHA não chega. O usuário pode acreditar que a senha aleatória de gerar-segredos.sh está em uso, mas não está. O impacto externo depende da exposição da API: o Compose atual publica em loopback. Não afirmo exploração remota confirmada.

### 3. Média: fluxo de depósito/documento não corresponde ao guia na instalação limpa

O guia promete depósito de teste, mas DEPOSITO_DEMO não é definido no perfil full; com .env vazio, o default é false. /pagamentos/depositar-demo recusa o depósito. KYC_DOCUMENTO_OBRIGATORIO também permanece no default true; a instalação não reproduz automaticamente a configuração de documentos opcionais da simulação usada localmente.

Correção indicada: definir e documentar os flags de simulação no perfil local, sem desligar biometria/DPoP. O teste realizado verificou configuração e defaults; não foi executado cadastro com câmera/documento físico.

### 4. Baixa: instalar o perfil recomendado depende de imagens de outro perfil

PARA-O-TIME recomenda install.sh para preparar o perfil full, que constrói código local, mas install.sh sempre tenta baixar as imagens do perfil Hub. Se um desses repositórios estiver indisponível, o instalador encerra antes do uso do perfil local, mesmo que os segredos já tenham sido criados. Um modo de instalação local deveria dispensar esse pull desnecessário.
